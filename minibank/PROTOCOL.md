MiniBank --- System Protocol & Working Guide
A practical guide to how the MiniBank source code is organized, how
its demonstrations run, and how account-related operations are
processed.

1. Purpose
MiniBank is an educational Java project covering OOP practicals and
related Java features. This document explains the program flow and
implementation responsibilities. It is not a network protocol, payment
gateway specification, or production banking security design.

3. Main Components
model.Account
The account model stores an account number, balance and interest rate.
It implements the Transactable and InterestBearing contracts,
supports serialization, and implements Comparable<Account>.

The implementation includes synchronized deposit and withdrawal methods:
- Deposit: accepts an amount only when it is greater than zero;
  otherwise it prints an invalid-deposit message.
- Withdrawal: returns false if the amount is zero/negative or
  greater than the current balance. Otherwise, it deducts the amount
  and returns true.
- Balance access: exposes the current balance through
  getBalance().
- Interest: exposes the configured rate; the relevant demo
  calculates yearly interest.
- Comparison: compares account numbers lexicographically through
  compareTo().
Account numbers are generated by a static counter in the current
process. This is suitable for a classroom example, not a robust globally
unique account-number service.
Interfaces and related types
- Transactable defines transaction-related behavior.
- InterestBearing defines the interest-rate contract.
- WithdrawRule provides a withdrawal rule that can be implemented
  with an anonymous class or a lambda.
- Premium is used in type / polymorphism demonstrations.
- model.annotation contains custom annotations such as Id,
  MaxLength and Positive.
Service layer
The service package contains the package-based entry point and
supporting demonstrations for areas including account storage, exception
handling, serialization, repository abstraction, transaction processing,
report generation and concurrency.
Utility layer
util.BankUtils contains shared helper functionality, including
formatted heading output. util.AnnotationValidator supports
annotation-based validation demonstrations.
4. Account Operation Protocol
A. Deposit
Receive deposit amount
        |
        v
Is amount greater than zero?
     /          \
   Yes           No
    |             |
    v             v
Add amount     Do not change
to balance     the balance
    |             |
    v             v
Operation ends / invalid-deposit message
The current Account.deposit() method does not return a success value.
Invalid deposits print a message and leave the balance unchanged.
B. Withdrawal
Receive withdrawal amount
        |
        v
Is amount <= 0 OR greater than balance?
        /                    \
      Yes                     No
       |                       |
       v                       v
Return false              Deduct amount
No balance change              |
                               v
                           Return true
A withdrawal is accepted only when the requested amount is positive and
does not exceed the available balance. The method is synchronized to
coordinate access to the balance when multiple threads use the same
account object.
C. Interest demonstration
The account stores an interest rate, and the relevant example invokes
yearlyInterest() to display the calculated yearly interest. The exact
formula and numeric representation should be checked in the source file
used by that demonstration before changing its implementation.
5. Main Program Execution
The package-based entry point is src/service/MiniBank.java, whose
fully qualified class name is service.MiniBank.

Its example flow is:
1. Create an account with an opening balance of ₹10,000 and a
   configured rate of 4.0.
2. Print the initial balance.
3. Deposit ₹2,000.
4. Print the updated balance.
5. Display yearly interest.
6. Execute a withdrawal through an anonymous WithdrawRule
   implementation.
7. Execute another withdrawal through a lambda implementation.
8. Print the final balance.
9. Demonstrate a runtime type check using instanceof Premium.
The root-level MiniBank.java is a separate default-package
demonstration. Because both source files use the class name MiniBank,
run them with the correct package/class name and compile target.
6. Validation and Exception Handling
The project includes custom annotations and a validation utility, as
well as custom exception classes such as account-not-found,
insufficient-funds and invalid-amount exceptions.

These files illustrate how validation and error conditions can be
represented in Java. Do not assume every demo invokes every validator
or exception: the execution path depends on the selected entry-point
class. Read that class to confirm which checks actually run.
7. Persistence, Logs and Reports
Supporting classes demonstrate serialization, state persistence, account
storage, transaction logging and report generation. These features may
read or write local files depending on the demo.

Before running such examples:
1. Use test data only.
2. Check the source for filenames and file paths.
3. Back up any important local files.
4. Do not store real customer information, passwords or financial
   credentials in the repository.
Generated runtime files are intentionally separate from the Java source
files and are excluded by the project's .gitignore where configured.
8. Concurrency Demonstrations
The repository includes examples related to thread safety, worker
threads, producer--consumer coordination and deadlock prevention.

When testing concurrency examples:
- Output order may differ between runs because threads can be
  scheduled differently.
- Shared mutable state requires appropriate synchronization or
  coordination.
- A demonstration illustrates a concept; it is not proof that a real
  banking workload is safe.
- Run each concurrency demo independently so its output is easier to
  understand.
9. Compile and Run
Run from the repository root.
Windows PowerShell
New-Item -ItemType Directory -Force out | Out-Null
javac -d out (Get-ChildItem -Recurse src -Filter *.java | ForEach-Object FullName)
java -cp out service.MiniBank
To compile the root-level demos as well:
javac -cp out -d out AccountWorker.java CustomerAccountDemo.java CustomerAccountMethodsDemo.java MiniBank.java MiniBankInterfaceDemo.java MiniBankPolymorphismDemo.java MiniBankValidationDemo.java
For example, run:
java -cp out MiniBankInterfaceDemo
Use the entry-point class appropriate to the concept you want to test.
10. Suggested Verification Sequence
1. Confirm java -version and javac -version work.
2. Compile the src tree.
3. Run service.MiniBank.
4. Compare the printed balances with the deposit and withdrawal
   operations.
5. Run the interface and polymorphism examples.
6. Run validation and exception demos.
7. Test persistence demos using disposable files.
8. Run concurrency demos individually and observe their behavior.
9. Check git status before committing changes, to avoid including
   generated data.
11. Limitations and Safety
MiniBank is a learning project, not production banking software. It does
not claim to provide production-grade authentication, authorization,
encryption, audit integrity, database transactions, regulatory
compliance or protection against all concurrency failures.

Do not connect it to real accounts, use real personal data, or treat its
local files as secure financial storage.
